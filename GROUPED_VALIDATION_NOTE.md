# Grouped cross-validation reproducibility reconciliation

**Date:** 6 November 2026  
**Scope:** The grouped five-fold validation only. No original research notebook or dataset was modified.

## Cause identified

The original saved `RevisedBN(4).ipynb` results were generated by the *historical* implementation of scikit-learn's `StratifiedGroupKFold(shuffle=True, random_state=42)`. A prior implementation shuffled the per-group class-count array without consistently updating its group-index mapping. The subsequent scikit-learn fix changed fold assignments, even with the same random seed.

I reproduced the historical algorithm in a separate diagnostic script and obtained the **exact** original test-set sizes: **788, 767, 830, 781, 854**. The current scikit-learn **1.8.0** implementation returned **805, 805, 803, 804, 803**. Both split schemes enforce group separation, but the historical folds have noticeably less balanced class proportions.

Official upstream report: https://github.com/scikit-learn/scikit-learn/issues/32478 (fixed in #32540).

**Interpretation:** Under the corrected grouped split, the hybrid still exceeds BN-only on accuracy and AUC, but no longer has better Brier score or log-loss. These particular grouped results cannot be presented as unchanged after a clean current-environment reproduction.

2. Store and distribute explicit group-fold assignments (`Grouped_CV_Fold_Assignments_Audit.csv`) so that future library changes do not affect the published validation splits.
3. Keep the original notebook intact as a historical audit record. Preserve the stratified main results, which reproduced independently.
4. Document scikit-learn version and distinguish the original historical fold assignments from the final corrected protocol.
